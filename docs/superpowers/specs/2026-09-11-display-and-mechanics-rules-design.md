# 展示精度与力学展示规范

**日期：** 2026-09-11  
**状态：** 已确认（待实现计划）  
**范围：** 全项目数值展示；力学场景的重力分力与静/动摩擦切换展示

## 目标

统一两套产品级规则，消除当前「各组件自选小数位、力学力系展示不一致」的问题：

1. **所有面向用户的计算/读数展示保留两位小数**
2. **力学相关实验**：重力必须给出切向/法向分力；静摩擦与动摩擦按物体状态切换，只展示当前生效项

## 已确认决策

| 决策点 | 结论 |
|--------|------|
| 两位小数作用域 | **仅展示层**（方案 A）：UI / 3D 标签 / 状态文案中的数 / 图表当前读数 / 参数旁当前值 |
| 引擎内部 | **不**每步强制两位；`tick`、积分、内部累计保持完整浮点 |
| 力学规则适用范围 | **项目级规范**（方案 B）：凡力学场景必须遵守；落地先从现有力学场景改起 |
| 重力分力语义 | **切向 / 法向**（方案 B）：\(G_t\)、\(G_n\)，服务教学受力分析 |
| 摩擦展示策略 | **只展示当前生效项**（方案 A）：静止→静摩擦块；滑动→动摩擦块 |

## 非目标

- 不修改物理公式与积分算法本身（除为对齐「状态判定单一来源」所必需的 derived 暴露）
- 不把 chart 历史采样在存储时截断为两位（仅展示读数按两位）
- 不把流体力学、天体力学等强行套用地面接触摩擦 UI（除非该场景明确建模静/动摩擦）
- 本次规范文档阶段不改代码；实现另开计划

## 规则 1：数值展示两位小数

### 1.1 适用范围

所有面向用户的数值，包括但不限于：

- 实时数据 overlay（`LiveDataOverlay`、`GenericLiveDataOverlay` 等）
- 摩擦力 / 力学信息 overlay
- 顶部 `StatusBar` / `detectStatus` 文案中嵌入的数字
- 3D 场景中的力、速度、标量标签
- 图表面板当前读数（标题旁数值）
- 参数滑条旁显示的当前参数值

### 1.2 格式约定

- 统一使用两位小数展示，例如 `12.30`、`0.00`
- **不因数值碰巧为整数而省略小数位**（避免 `12` 与 `12.30` 混用）
- 非法 / 非有限值：展示层显示为 `—` 或 `0.00`（实现时二选一并全项目统一；推荐 `—`）

### 1.3 实现约束

- 提供公共格式化工具（建议 `formatQuantity(n: number): string` → `n.toFixed(2)`，并对非有限值做守卫）
- 展示层禁止再各自选择 `toFixed(0|1|3)` 等不同精度
- 物理 `tick`、能量累计、历史数组**保持**完整精度

### 1.4 验收

- 抽查任意场景：overlay、状态文案数字、3D 标签、图表读数、滑条旁数值均为两位
- `pull-friction` 回归：动能 / 功热等读数仍为两位，仿真行为与改前一致（允许显示四舍五入差异）

## 规则 2：力学场景力与摩擦展示

### 2.1 何为「力学场景」

- **定义：** 首页目录 `domain` 为「经典力学」，或场景显式声明属于地面接触 / 牛顿质点受力分析类力学实验
- **当前落地对象：** `pull-friction`（`src/scenes/pullFriction/`）
- **日后新增：** 凡符合上述定义的场景，必须在设计阶段遵守本规则；流体、天体等仅在建模了同类接触摩擦时才套用 §2.3

### 2.2 重力切向 / 法向分力

在场景受力分析坐标系下，重力 \(mg\) **必须**同时给出：

| 符号 | 含义 |
|------|------|
| \(G_t\) | 重力沿**可能运动方向**（切向）的分量 |
| \(G_n\) | 重力沿**法向**（垂直接触面、指向/压向表面）的分量 |

**展示要求：**

- 实时数据中可见 \(G_t\)、\(G_n\)（可同时保留 \(mg\) 总量）
- 3D 或等价分解标注中，能与法向支持力 \(N\)、拉力法向分量对照

**水平面 `pull-friction` 约定：**

- \(G_t = 0\)
- \(G_n = mg\)
- 与既有关系 \(N = G_n - F\sin\theta\)（未离地时）一致

斜面等未来力学场景：按该场景定义的切向/法向轴分解，不得只显示标量 \(mg\) 而无分力。

### 2.3 静 / 动摩擦：按状态只展示当前生效项

| 物体状态 | 展示内容 | 不展示 |
|----------|----------|--------|
| 静止（静摩擦锁住 / 未起动） | 静摩擦相关：实际 \(f_s\)、\(f_{s,\max}\)，及必要的 \(\mu_s\) | 动摩擦数值块（\(f_k\)、\(\mu_k\) 作为「当前摩擦」） |
| 滑动 | 动摩擦相关：\(f_k\) / 实际滑动摩擦力 \(f\)，及必要的 \(\mu_k\) | 静摩擦数值块（\(f_s\)、\(f_{s,\max}\)、\(\mu_s\) 作为「当前摩擦」） |
| 离地 / 无接触 | 标明摩擦不适用；不强行给出静或动摩擦「当前值」 | 伪造的接触摩擦力 |

**状态判定：**

- 必须以物理引擎 / `detectStatus`（或引擎暴露的同一状态枚举）为**唯一来源**
- Overlay、3D 标签不得各写一套互相冲突的静/动判定

**参数区说明：** 参数滑条上的 \(\mu_s\)、\(\mu_k\) **输入控件可以同时存在**（用户需要调节）；本规则约束的是**结果展示 / 力分析展示**，不是禁止参数输入。

### 2.4 `pull-friction` 现状与目标差距（供实现对照）

当前已知不一致（实现时应消除）：

- 小数位在 overlay / 3D / 状态文案中为 0/1/2 混用
- 重力常只显示标量 \(mg\)，缺少明确的 \(G_t\) / \(G_n\) 展示
- 静/动摩擦相关量有时同时列出，未按状态切换「只展示当前生效项」
- 部分 overlay 可能用参数 \(F\) 而非能量限制后的 \(F_\text{actual}\) 重算，存在与引擎不一致风险

## 推荐落地结构（实现阶段）

```
src/lib/formatQuantity.ts          # 或 src/utils/format.ts — 公共两位格式化
ScenePage overlays / Charts / ParamSliders / Status 文案
pullFriction Scene3D 力标签
pullFriction physics derived 暴露 Gt, Gn, frictionMode 等供 UI 只读
```

建议在 `derived`（或 status 扩展）中显式输出：

- `G_t`, `G_n`, `mg`
- `frictionMode: 'static' | 'kinetic' | 'none'`（若类型系统不便放 string，可用并列 boolean / 枚举 number，由 UI 映射）
- 当前生效摩擦大小与对应上限（静：`f_s`, `fs_max`；动：`f_k`）

## 验收清单

### 规则 1

- [ ] 公共 `formatQuantity` 存在且展示层统一使用
- [ ] 抽查 ≥3 个非力学场景 + `pull-friction`：读数均为两位
- [ ] 物理回放 / 能量关系不因「仅改展示」而数值漂移（引擎层未截断）

### 规则 2（`pull-friction`）

- [ ] 可见 \(G_t\)、\(G_n\)，水平面下数值符合 \(G_t=0,\ G_n=mg\)
- [ ] 静止时只出现静摩擦结果展示；滑动时只出现动摩擦结果展示
- [ ] 离地时不显示「当前静/动摩擦」有效值
- [ ] Overlay 与 3D / Status 的静动判定一致
- [ ] 所有新展示数字遵守规则 1

---

## 风险与注意

- 状态文案里嵌入数字若漏改，会出现「面板两位、句子一位」；实现时需全文检索 `toFixed`
- 「只展示当前摩擦」不要误删参数滑条上的 μₛ/μₖ
- 图表曲线点保持原始精度，仅当前值标签两位，避免历史被二次量化
